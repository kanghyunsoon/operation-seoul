## 2. 에피소드 목록 UI 트러블슈팅

### 증상

- 페이지네이션과 하단 네비가 붙거나 겹쳐 보임.
- AI 버튼이 우하단에 너무 붙거나, 네비/카드와 위치 기준이 어긋남.
- 한 화면 고정 요구 때문에 카드 목록과 하단 영역이 서로 공간을 빼앗음.

### 원인

- 하단 네비는 fixed인데 페이지네이션은 일반 흐름 또는 fixed를 오가며 기준이 일관되지 않았다.
- `height: 100dvh`와 `overflow: hidden` 조건 때문에 화면 높이가 낮으면 하단 영역이 쉽게 충돌한다.
- 2열 x 3행 카드, 페이지네이션, 하단 네비, AI 버튼을 모두 같은 화면에 넣으려면 카드 높이와 네비 위치를 고정 수치로만 제어하기 어렵다.

### 권장 해결안

1. 하단 네비 높이를 CSS 변수로 정의한다.
2. 페이지 전체를 grid로 나누고, 하단 고정 영역 높이를 명시한다.
3. 페이지네이션은 fixed가 아니라 본문 흐름에 두되, 네비 영역만큼 padding을 확보한다.
4. 768px 이하 높이에서는 카드 3행을 유지하지 않고 2행 + 페이지 이동 또는 내부 list scroll을 허용한다.

예시 방향:

```css
.episode-page {
  --bottom-nav-space: 112px;
  height: 100dvh;
  display: grid;
  grid-template-rows: auto minmax(0, 1fr) auto;
  padding-bottom: var(--bottom-nav-space);
}

.episode-list {
  min-height: 0;
}

@media (max-height: 760px) {
  .case-card p,
  .meta {
    display: none;
  }
}
```

## 6. AI 오케스트레이션 구조 개선 트러블슈팅

### 문제 상황

초기 구조에서는 TourAPI 기반 관광·역사 정보와 Kakao Map 기반 위치·장소 정보가 하나의 RAG 흐름 안에서 함께 보완되었다. 이 때문에 역사적 배경을 생성해야 하는 단계에 위치·경로 중심 정보가 섞였고, 이후 키워드 생성 AI가 실제 장소명이나 지도 기반 정보를 사건의 핵심 키워드로 잘못 반영하는 데이터 오염 문제가 발생했다.

### 원인

- TourAPI는 관광·역사·문화 맥락에 강하고, Kakao Map/Kakao Local은 위치·경로·주변 장소 정보에 강하다.
- 성격이 다른 데이터를 하나의 프롬프트/RAG 입력으로 합치면서 AI가 어떤 정보를 스토리 생성 근거로 써야 하는지 구분하지 못했다.
- 스토리, 키워드, 단서 생성을 하나의 AI 호출에서 프롬프팅만으로 통제하려 하면서 한 단계 수정이 다른 단계 품질을 깨뜨렸다.

### 개선 내용

AI 호출 구조를 역할별로 분리했다.

1. TourAPI 기반 장소 정보를 RAG로 보완하여 역사적·문화적 배경 데이터를 생성한다.
2. 보완된 배경 데이터를 바탕으로 방탈출 장르에 맞는 최종 키워드, 즉 범인·동기·흉기·방법을 생성한다.
3. 생성된 키워드를 기반으로 사건 스토리를 생성한다.
4. 완성된 스토리를 바탕으로 용의자 카드, 미션 카드, 조사 단서를 생성한다.
5. 유저가 수집한 단서를 바탕으로 최종 추리 단계에서 문답식 힌트를 제공한다.
6. 유저가 입력한 최종 정답 문장이 핵심 키워드 4개를 포함하고 있는지 문장 유사도 기반으로 검증한다.

### 결과

- 관광·역사·문화 맥락과 위치·경로·장소 정보가 섞이는 문제를 줄였다.
- 실제 장소 정보는 위치 기반 미션 구성에 활용하고, 사건 스토리와 추리 키워드는 역사적·문화적 배경에 근거하도록 구조를 분리했다.
- 각 AI 단계의 산출물을 다음 단계 입력으로 넘기는 AI 오케스트레이션 구조가 되어 디버깅과 품질 보정이 쉬워졌다.

- `GeminiDraftPromptBuilder`
- `TourApiPlanInputExtractor`

## 7. AI 응답 UX 개선: 비동기 타자기 버퍼

### 문제 상황

AI 응답을 기다리는 시간이 길게 느껴졌고, 응답이 한 번에 표시되면 사용자가 지연을 더 크게 체감했다.

### 개선 내용

- AI 응답 문맥을 유지하면서 화면에 순차적으로 노출하는 비동기 타자기 효과를 적용했다.
- 응답 문자열을 버퍼에 저장하고 일정 간격으로 출력하여 사용자가 AI가 답변 중이라는 피드백을 받도록 했다.

관련 위치:

- `frontend/src/composables/useTypingBuffer.js`
- AI 추천/코칭/추리 응답 표시 화면

## 8. 프롬프트/필터링 품질 개선

### 문제 상황

초기 프롬프트로 생성한 AI 응답 품질이 낮아 fallback 필터링과 내용 수정 로직을 강화했다. 하지만 필터링이 너무 강해지면서 정상 응답까지 막히고, 결과물에 노이즈가 생겼다.

### 개선 내용

- 필터링을 단순화하여 반드시 막아야 하는 오류만 검출하도록 조정했다.
- 핵심 차단 항목은 정답 키워드 유출, 흉기와 동기의 부자연스러운 관계, 최종 장소 직접 노출 등으로 제한했다.
- 프롬프트 자체를 강화하여 AI가 처음부터 의도한 구조로 스토리와 단서를 생성하도록 수정했다.

관련 위치:

- `AiEpisodeDraftValidator`
- `AiDraftTextQualityValidator`
- `DraftCrimeMysteryGuardrailApplier`
- `DraftFinalTruthGuardrail`
- `DraftNarrativeGuardrail`
- `GeminiDraftPromptBuilder`

## 9. 로그 기반 AI 품질 분석

### 문제 상황

초기에는 상세 로그 없이 AI 응답 결과만 보고 프롬프트를 수정했다. 이 방식은 한 부분을 고치면 다른 단계 품질이 깨지는 문제가 반복됐다.

### 개선 내용

- `slf4j` 기반 로그를 남겨 AI 입력, 중간 산출물, fallback 적용 지점, validation 실패 사유를 추적했다.
- 상세 로그 분석을 통해 프롬프팅과 fallback 조건을 세부적으로 조정했다.
- AI 응답 품질 이슈를 “결과만 보고 추정”하지 않고 단계별 원인으로 분리할 수 있게 되었다.

보완 필요:

- 운영 환경에서는 개인정보/정답 키워드/외부 API key가 로그에 남지 않도록 masking 정책이 필요하다.

## 10. 데이터 증가와 페이징 처리

### 문제 상황

콘텐츠 양이 늘어나면서 에피소드 목록에서 스크롤해야 하는 불편함이 커졌다. 프론트 개발 서버를 오래 켜 둔 상태에서 많은 컨텐츠를 반복 렌더링하면 체감 렉도 발생했다.

### 개선 내용

- 에피소드 목록에 페이징을 적용했다.
- 백엔드는 `limit`, `offset` 기반으로 필요한 구간만 순차 조회하도록 구성했다.
- 프론트는 페이지 버튼으로 현재 구간만 렌더링해 한 번에 표시하는 카드 수를 제한했다.

관련 위치:

- `EpisodePlayController`
- `EpisodePlayService`
- `EpisodeRepository`
- `EpisodeListView.vue`

보완 필요:

- 검색/정렬 조건과 함께 pagination query를 유지해야 한다.
- 총 개수, 현재 페이지, 마지막 페이지 계산을 사용자에게 더 명확히 보여줄 수 있다.

## 11. AI 추천/코칭 필수 기능화에 따른 보완 계획

### 현재 상태

- 추천: 관심 에피소드, 일정, 클리어 기록 등을 기반으로 추천 후보를 계산한다.
- 코칭: 플레이 기록 기반으로 규칙형 요약과 조언을 제공한다.
- 현재 구조는 “AI 기능 MVP”로는 설명 가능하지만, 필수 기능으로 평가될 경우 생성형 AI 호출과 응답 품질 관리가 더 필요하다.

### 보완 방향

1. 추천 후보 산출은 기존 규칙 엔진으로 유지한다.
2. 산출된 후보와 사용자 플레이 요약을 Gemini에 전달해 추천 이유와 다음 플레이 전략을 생성한다.
3. 코칭은 클리어 시간, 실패 횟수, 선호 장르, 단서 수집 패턴을 요약해 Gemini가 개인화 피드백을 생성한다.
4. Gemini 실패 시 기존 규칙 기반 추천/코칭을 fallback으로 반환한다.
5. 응답에는 “추천 근거 데이터”와 “AI 생성 설명”을 분리해서 표시한다.

권장 수정 위치:

- `EpisodeRecommendationService`
- `EpisodeRecommendationController`
- `CoachingService`
- `CoachingController`
- `RecommendationsView.vue`
- `CoachingView.vue`
- `GeminiContentClient`
